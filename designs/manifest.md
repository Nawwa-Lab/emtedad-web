# UI migration manifest

`status`: `done` = completed/out of scope, `existing` = a matching Next route exists but needs visual comparison, `proposed` = dashboard route requires approval before creation, `migrated` = implemented and linted.

## Agent workflow

For one migration batch, read only the selected rows and their source HTML. Convert source CSS to element-level Tailwind utilities, implement the `Target Next.js file`, reuse the modules in `Reuse first`, and use `components/ui/*` for the appropriate existing primitive. Use the applicable dashboard layout before creating a new layout. Inspect `icons/` before using an SVG; reuse a matching `@/icons/*.svg` asset or request approval if none matches. Put feature copy in its domain locale JSON and cross-domain business copy in `global.json`; keep dynamic states in typed route-local `data.ts` fixtures. Do not create a shared component unless at least two approved rows need it; record that component in both rows when created. Update the row to `migrated` only after the route is implemented and linted.
